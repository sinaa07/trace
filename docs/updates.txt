--- Iteration 1 | 2026-08-23 | Phase 1: Case Ingestion ---

- Entity normalization (train/signal ID aliases)
- Unit normalization (speed, temperature, etc.)
- Raw + normalized values preserved in field_provenance
- Malformed rows retained with is_valid=false and parse_warnings

INGESTION PIPELINE (IngestionOrchestrator)
- Upload → hash → store raw → parse → clean → persist records → manifest → audit
- processing_status lifecycle: pending → parsing → cleaning → completed | failed

API ENDPOINTS (live)

--- Iteration 2A | 2026-08-24 | Domain Processing Profiles ---

- Each source_type cleans via its own server-side ProcessingProfile strategy
- Shared ingest pipeline + shared EvidenceRecord storage (no per-domain private stores)
- Declared source_type is authoritative; scored matching sets needs_review on conflict/low confidence

PROCESSING PROFILES (backend/app/core/processing/)
- ProcessingProfile + MatchConfig + ProfileSelection
- ProcessingProfileRegistry loads versioned YAML profiles
- Deterministic matcher scores headers / filename / content hints
- DomainProcessor applies profile field maps, validators, entity/unit transforms
- Profiles: signal_log_v1, train_telemetry_v1, maintenance_v1, weather_v1, witness_v1, other_v1

INGESTION UPDATES
- IngestionOrchestrator dispatches DomainProcessor.select_and_clean after parse
- Artifact fields: profile_id, match_score, match_reasons, needs_review
- Alembic migration 002_profile_metadata
- Manifest + audit payload include profile selection metadata
- RecordCleaner kept as thin compatibility wrapper

TESTS

- Ingestion e2e asserts profile_id on signal_log upload
- Suite: 21 passing

--- Local Dev Setup | 2026-08-25 | Docker + Postgres ---

DOCKER COMPOSE (docker-compose.yml)
- Postgres host port changed 5432 → 5433 to avoid conflict with local macOS Postgres on 5432
- Credentials: user trace, password trace_pass, database trace
- Fresh init: docker compose down -v && docker compose up -d postgres

ENV (backend/.env.example, backend/.env)
- DATABASE_URL=postgresql+psycopg://trace:trace_pass@localhost:5433/trace
- Copy .env.example → .env before running backend or Alembic

MIGRATIONS (first-time schema)
- No manual table creation required; Alembic creates all tables
- From backend/: alembic upgrade head (applies 001_initial + 002_profile_meta + 003_events)
- Verify: docker compose exec postgres psql -U trace -d trace -c '\dt'
- Expected tables: cases, evidence_artifacts, evidence_records, events, audit_log, alembic_version

TROUBLESHOOTING
- "role trace does not exist" on localhost:5432 → Alembic hit local Postgres, not Docker; use port 5433 or stop local Postgres
- Password changes in docker-compose.yml only apply on first volume init; use docker compose down -v to recreate
- DATABASE_URL user/password/port must match docker-compose.yml exactly
